# Промт: TrustMe Admin — панель управления нодами TrustMe

> Документ для агента или разработчика, который строит панель. Это одновременно
> ТЗ: решения владельца здесь окончательные, пересматривать их не нужно.
> Прежде чем брать этап в работу, прочитай документ целиком.

## 1. Что строим

**TrustMe Admin** — самостоятельно разворачиваемый сервис с веб-панелью для
управления нодами мессенджера TrustMe (сервер — `trustme_backend`, крейт
`trust_message_tcp`).

Кто его ставит — любой, у кого есть нода:

- **Один человек и одна нода.** Админка стоит на том же хосте и показывает,
  здорова ли нода, хватает ли места, не потерян ли ключ.
- **Команда или компания и парк нод.** Админка на отдельном хосте: десятки
  нод сотрудников, доступы, обновления по частям парка.

Мультиарендности нет: **одна установка — один владелец** (человек или
команда с несколькими администраторами).

Продукт должен быть **удобным, функциональным и выразительным**: открыл —
и за две секунды видно, всё ли в порядке и что чинить.

## 2. Окружение и связанные проекты

| Что | Где | Зачем админке |
|---|---|---|
| Нода `trust_message_tcp` | `github.com/Darkildo/trustme_backend` | что мы администрируем |
| `tmnode` | там же, крейт `tmnode/` | проверка ноды; в будущем — агент на хосте |
| `net::probe` | `trust_message_tcp::net::probe` | проверка ноды снаружи путём клиента |
| Контракт `node.toml`, схема 1 | `trustme_backend/docs/tmnode.md` | желаемое состояние ноды |
| Контракт отчёта `tmnode.report/1` | там же | отчёты `tmnode doctor` |
| Протокол клиента | `trustme_backend/server-contract.md` | семантика `ServerConfig` и возможностей |
| Метрики ноды | `trustme_backend/docs/runbook-metrics.md` | Prometheus-текст, префикс `trust_message_tcp_` |

Ключевые факты о ноде, которые нужно знать:

- **Ключ.** Клиент подключается по Noise IK и обязан заранее знать
  публичный ключ ноды — **пин**, 32 байта X25519, 64 hex. Без пина
  подключиться нельзя, поэтому пин — главное свойство ноды в админке.
- **Потеря ключа отрезает всех клиентов.** Сигналы такой аварии:
  `identity.secret` / `identity.pin` в отчёте и метрика
  `node_key_source{source="generated"}`.
- **Подписанный `ServerConfig`.** Нода отдаёт его с флагами возможностей:
  `supports_blobs`, `supports_delivery_ack`, `supports_queue_addressing`
  и т.д.
- **Запуск.** Нода работает в Docker (`message-service`) на бэкенде `sled`
  или `jetstream`.

## 3. Решения владельца (окончательные)

| Тема | Решение |
|---|---|
| Репозиторий | `github.com/Darkildo/trustme_admin`, публичный; лицензия как у бэкенда: PolyForm Strict 1.0.0 + LICENSING.md + CLA |
| Сервер | Rust (edition 2024), **axum**, tokio, **sqlx** |
| Хранилище | **SQLite** (файл рядом с бинарём). Postgres можно добавить позже, поэтому SQL держим переносимым |
| Фронтенд | **React + Vite + TypeScript (strict)**, Tailwind CSS, shadcn/ui (Radix), TanStack Query и TanStack Router, ECharts, Motion, lucide-react |
| Поставка | **один бинарь** `trustme-admin`: API и собранная панель встроены в него. Плюс Docker-образ и `compose.yaml` |
| Вход | пароль (argon2id) + **TOTP**; первый администратор создаётся по одноразовой ссылке из лога первого старта |
| Дизайн | **тёмная «ops»-эстетика** по умолчанию, светлая тема переключателем |
| Язык интерфейса | русский основной, английский — вторым (i18n с первого дня) |
| Агент на хосте ноды | `tmnode agent` в репозитории бэкенда, **исходящее** соединение к админке. На сервере ноды входящий порт не открывается |

## 4. Архитектура

```
 браузер ──HTTPS──► trustme-admin ──SQLite (admin.db)
                      │   ▲
   probe (Noise IK) ──┘   │ ingest / agent (исходящие от хостов нод)
          ▼               │
     ноды TrustMe ◄── tmnode doctor --json | curl   (этап 1)
                  ◄── tmnode agent                  (этап 2)
```

- **Сервер** — один процесс:
  - REST API `/api/v1/*` (JSON);
  - статика панели (встроена через `rust-embed`, SPA-fallback на `index.html`);
  - планировщик проб;
  - чистка истории.
- **Пробы.** Сервер сам проверяет каждую ноду снаружи через
  `trust_message_tcp::net::probe` (git-зависимость на `trustme_backend`,
  закреплённая по rev). Так видна доступность ноды с точки зрения клиента
  даже без агента.
- **Отчёты.** На этапе 1 хост ноды присылает отчёт `tmnode doctor --json`
  по токену ноды (cron + curl). На этапе 2 это делает агент.
- **Типы контрактов.** Отчёт `tmnode.report/1` админка разбирает **по
  JSON-контракту**, своими типами:
  - незнакомые проверки и ключи `data` не ломают разбор;
  - неизвестный `format` — отказ с понятной ошибкой.

## 5. Модель данных (SQLite, миграции sqlx)

- `users` — `id`, `username` (уникальный), `password_hash` (argon2id),
  `totp_secret` (шифрованный или NULL), `role` (`owner` / `admin` /
  `viewer`), `created_at`, `last_login_at`, `disabled`.
- `sessions` — `id`, `user_id`, `token_hash` (SHA-256 случайных 32 байт),
  `created_at`, `expires_at`, `last_seen_at`, `user_agent`, `ip`.
- `setup_tokens` — одноразовый токен первичной настройки (хэш, срок).
- `nodes`:
  - адрес и пин: `id` (ULID), `name`, `addr` (`host:port`), `node_key`
    (64 hex, пин);
  - метаданные: `labels` (JSON), `notes`;
  - отчёты: `ingest_token_hash`;
  - пробы: `probe_interval_secs` (по умолчанию 60), `paused`;
  - `created_at`, `updated_at`.
- `probes` — `id`, `node_id`, `at`, `ok`, `stage` (`connect` /
  `handshake` / `auth` / `config` / NULL), `error`, `connect_ms`,
  `handshake_ms`, `config` (JSON: версия протокола, флаги, `expires_at`).
- `reports` — `id`, `node_id`, `received_at`, `generated_at`, `status`,
  `counts` (JSON), `body` (полный JSON отчёта), `tmnode_version`.
- `audit` — `id`, `at`, `user_id` (или NULL — система), `action`,
  `target`, `details` (JSON), `ip`.

Хранение:
- **Пробы** — 14 суток (настраивается).
- **Отчёты** — последние 500 на ноду.
- **Аудит** — бессрочно.
- Секреты хранятся только хэшами. Исключение — TOTP-секрет, он шифруется
  ключом из файла `secret.key` рядом с базой.

## 6. API (этап 1)

Общие правила:
- Всё под `/api/v1`, JSON.
- Ошибки — `{ "error": { "code": "...", "message": "..." } }`.
- Изменяющие запросы требуют сессионную cookie
  (`HttpOnly; SameSite=Strict; Secure` при HTTPS) **и** заголовок
  `X-TrustMe-Admin: 1` (защита от CSRF).

| Метод | Путь | Что делает | Права |
|---|---|---|---|
| GET | `/health` | `{ status, version }`, без входа | все |
| GET | `/setup` | нужна ли первичная настройка | все |
| POST | `/setup` | `{ token, username, password }` → первый `owner` | по токену |
| POST | `/auth/login` | `{ username, password, totp? }` → cookie; `totp_required`, если код нужен | все |
| POST | `/auth/logout` | | вошедший |
| GET | `/auth/me` | пользователь, роль, включён ли TOTP | вошедший |
| POST | `/auth/totp/setup` | секрет и `otpauth://` URI (для QR) | вошедший |
| POST | `/auth/totp/enable` | `{ code }` | вошедший |
| POST | `/auth/totp/disable` | `{ password, code }` | вошедший |
| POST | `/auth/password` | `{ current, new }` | вошедший |
| GET | `/overview` | сводка парка: ноды по статусам, последние события, доступность за 24 ч | viewer+ |
| GET | `/nodes` | список: последний статус пробы и отчёта, задержка, метки | viewer+ |
| POST | `/nodes` | `{ name, addr, node_key, labels? }` → нода + **ingest-токен (показывается один раз)** | admin+ |
| GET | `/nodes/{id}` | карточка: последний отчёт целиком, последний конфиг, расхождения | viewer+ |
| PATCH | `/nodes/{id}` | имя, адрес, пин, метки, заметки, интервал, пауза | admin+ |
| DELETE | `/nodes/{id}` | | admin+ |
| POST | `/nodes/{id}/probe` | проверить сейчас | admin+ |
| GET | `/nodes/{id}/probes?since=&limit=` | история проб для графиков | viewer+ |
| GET | `/nodes/{id}/reports?limit=` | история отчётов (без body) | viewer+ |
| GET | `/nodes/{id}/reports/{rid}` | отчёт целиком | viewer+ |
| POST | `/nodes/{id}/ingest-token` | выпустить новый токен, старый отзывается | admin+ |
| POST | `/ingest/report` | `Authorization: Bearer <ingest-token>`, тело — `tmnode.report/1` | токен ноды |
| GET | `/users` | | owner |
| POST | `/users` | `{ username, role }` → ссылка-приглашение (одноразовая, 48 ч) | owner |
| PATCH / DELETE | `/users/{id}` | роль, блокировка | owner |
| GET | `/audit?limit=&before=` | журнал | admin+ |

Статус ноды для списков и сводки:
1. Берутся статус последней пробы (`ok` / `fail`) и последнего отчёта.
2. Отчёт старше трёх интервалов cron считается устаревшим (`stale`).
3. Итог — худший из них: `ok` < `unknown` < `warn` < `stale` < `fail`.

## 7. Безопасность

- **Привязка.** По умолчанию сервер слушает `127.0.0.1:8088`.
  - Наружу — через обратный прокси с TLS; в README есть готовый фрагмент
    для Caddy.
  - Или `--listen 0.0.0.0:8088` с предупреждением в логе, если TLS не
    настроен.
- **Пароли:** argon2id с параметрами OWASP; минимум 10 символов.
- **Перебор паролей.** Rate-limit входа по IP и по логину: после пяти
  неудач пауза 30 с, дальше вдвое длиннее, до 15 минут; событие в аудит.
- **TOTP:** RFC 6238, окно ±1 шаг, повтор кода запрещён (запоминается
  последний использованный шаг).
- **Сессии:** 12 ч скользящего срока, 7 суток максимум. Выход гасит
  текущую сессию, смена пароля — все остальные сессии пользователя.
- **Ingest-токен:**
  - 32 случайных байта, в базе только SHA-256, сравнение за постоянное
    время;
  - отчёт — до 256 КиБ, не чаще раза в 10 с на ноду;
  - отчёт не того формата → 422.
- **Секреты нигде не логируются**: токены, пароли, TOTP. Пин ноды —
  публичный, его показывать можно.
- **Аудит:** вход и выход, неудачный вход, TOTP вкл/выкл, создание,
  изменение и удаление ноды, выпуск токена, управление пользователями.
- **Заголовки:** CSP без внешних источников (шрифты и иконки свои, не
  CDN), `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors
  'none'`.

## 8. Дизайн и UX

**Направление:** тёмная «ops»-эстетика в духе Linear, Vercel и Grafana.
Плотная, информативная, спокойная, но с выразительными акцентами там, где
важно.

- **Палитра.**
  - Фон — глубокий графит, не чистый чёрный (`#0B0D12`); поверхности на
    1–2 ступени светлее, тонкие границы `white/6–10%`.
  - Акцент — один насыщенный цвет бренда: электрический бирюзовый
    `#2DD4BF`, с фиолетовым градиентом для героев и пустых состояний.
  - Статусы: ok — изумрудный, warn — янтарный, fail — красный, stale и
    unknown — серо-голубой, skip — нейтральный.
  - Статус всегда дублируется формой или иконкой, а не только цветом.
- **Типографика:** Inter (интерфейс) и JetBrains Mono (адреса, ключи,
  числа, ID), через `@fontsource`, без CDN. Табличные цифры в метриках.
- **Токены.** Все цвета, радиусы, тени и отступы — CSS-переменные на
  `:root` и `[data-theme=light]`. Компоненты не знают конкретных цветов.
- **Каркас:**
  - левый сайдбар (Обзор, Ноды, Журнал, Пользователи, Настройки),
    сворачивается;
  - верхняя панель с поиском и командной палитрой **⌘K / Ctrl+K**:
    переход к ноде, «проверить сейчас», «добавить ноду»;
  - тосты; переключатель темы и языка.
- **Обзор:**
  - крупная сводка «N нод: x в порядке · y внимание · z сломаны» с живым
    индикатором;
  - карта-сетка нод: плитка — статус, имя, задержка, sparkline доступности
    за 24 ч;
  - лента событий (смена статуса, новые отчёты с проблемами);
  - график задержки рукопожатия по парку.
- **Список нод:**
  - таблица с сортировкой и фильтрами по статусу и меткам;
  - моно-шрифт для адресов;
  - копирование пина в один клик с отпечатком `A1B2-C3D4-…`.
- **Карточка ноды:**
  - шапка: имя, статус-бейдж, адрес, пин с копированием, версия протокола
    и флаги возможностей чипами;
  - вкладки:
    - **Состояние** — 15 проверок последнего отчёта, сгруппированные:
      Конфиг, Рантайм, Ключ, Ресурсы, Сеть. Подсказки `hint` подсвечены
      как действие;
    - **История** — графики задержки connect/handshake, лента
      доступности, история отчётов;
    - **Подключение** — инструкция и готовая команда cron для
      `tmnode doctor --json | curl …` с подставленным токеном, выпуск
      нового токена;
    - **Настройки** — имя, метки, интервал, пауза, удаление с
      подтверждением вводом имени.
- **Мастер «Добавить ноду»:** шаги «адрес и пин» → «проверка» (живая
  проба с анимацией этапов TCP → рукопожатие → конфиг) → «отчёты» (токен и
  команда).
- **Пустые состояния** с иллюстрацией-градиентом и одной ясной кнопкой.
- **Движение.** Плавные переходы (Motion), скелетоны при загрузке;
  `prefers-reduced-motion` отключает анимации.
- **Доступность:** контраст AA, фокус-кольца, вся навигация с клавиатуры,
  aria-метки у иконок.
- **Адаптивность:** от 360 px. На телефоне сайдбар становится нижней
  навигацией, таблицы — карточками.

## 9. Этапы

**Этап 1 — фундамент (сейчас):**
- репозиторий, лицензия, CI;
- сервер: конфиг, SQLite, миграции, первичная настройка, вход с TOTP,
  сессии, пользователи и роли, аудит;
- ноды, пробы по расписанию, приём отчётов `tmnode doctor`;
- панель: все экраны раздела 8;
- Docker-образ и `compose.yaml`;
- установка одной командой: `docker compose up -d`, а затем ссылка из
  лога.

**Этап 2 — агент:**
- `tmnode agent` с подключением к админке по одноразовому токену
  (`tmnode enroll`);
- отчёты и метрики по исходящему соединению;
- желаемое состояние из `node.toml` и `config.drift` на экране;
- кнопка «Скопировать команду установки» для новой ноды.

**Этап 3 — доступ к нодам.** Требует изменений в ноде, это отдельное ТЗ в
бэкенде:
- инвайт-коды: одноразовые и универсальные, срок, лимит, QR со ссылкой
  `tm://node?...`;
- whitelist аккаунтов;
- уровни «участник» и «отправитель»;
- отзыв допущенных по коду.

**Этап 4 — обновления:** каналы `stable` / `pinned`, раскатка по частям
парка, откат.

**Этап 5 — ретранслятор пушей:** регистрация нод в ретрансляторе,
лимиты.

## 11. Качество

- **Rust:**
  - `cargo fmt --check`;
  - `cargo clippy --all-targets -- -D warnings`;
  - `cargo test`: интеграционные тесты API на временной базе, тест пробы
    против ноды, поднятой в процессе;
  - `cargo audit`.
- **Web:**
  - `pnpm lint` (ESLint), `pnpm typecheck`;
  - `pnpm test` (Vitest + Testing Library на ключевых компонентах:
    статусы, мастер, форма входа);
  - `pnpm build`.
- **CI в GitHub Actions:** сторонние actions закреплены SHA коммита (как в
  бэкенде).
- **Сообщения коммитов** — на русском, в стиле бэкенда (`feat(api): …`),
  **без строк соавторства и атрибуции**.
- **Правило для логов:** токены, пароли, TOTP-коды и секреты не логируются
  никогда.

## 12. Не делаем

- Мультиарендность, биллинг, регистрацию «для всех».
- Сбор содержимого переписки или метаданных пользователей нод. Админка
  видит здоровье ноды, а не людей.
- Внешние CDN, трекеры и аналитику.
