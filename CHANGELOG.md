# Изменения

## 0.3.1

- **Адресация по очередям — переключателем.** Настройку
  `queue_addressing_enabled` (нода с 0.8.0) панель показывает
  переключателем «включено/выключено». `/catalog` отдаёт `since` — версию
  ноды, с которой она знает настройку; ноде старше панель такую настройку
  в `runtime.toml` не кладёт (иначе нода отвергла бы весь файл), а баннер
  применения показывает её как неотправленную.
- Бэкенд `trustme_backend` v0.8.2 (было v0.8.0): совместимые обновления
  зависимостей, протокол без изменений.
- `russh` 0.65: исправления безопасности SSH-клиента (GHSA-4p9f-7p9m-5vfg,
  GHSA-fw5c-8223-6h42); совместимые обновления остальных зависимостей.
- Образ Docker на `rust:1.99-slim-bookworm`.

## 0.3.0

- **Обновление нод из панели.** Нода (образ контейнера) и агент `tmnode`
  обновляются до версий из релизов бэкенда: выбор версии, понижение только
  явной галочкой, ход по шагам агента (проверка → `tmnode` → образ →
  пересоздание → проверка ноды, откат при неудаче), отмена до начала,
  история на вкладке «История». Задание без вестей от агента 15 минут
  помечается потерянным.
- Релизы берутся из GitHub API (`TM_ADMIN_RELEASES_REPO`, по умолчанию
  `Darkildo/trustme_backend`; `off` — версии вручную), хэш `tmnode` — из
  `SHA256SUMS` релиза под архитектуру агента.
- Обновляться из панели умеет tmnode 0.7.0 и новее (с v0.7.0 версия tmnode
  совпадает с версией релиза). Агенту старше панель показывает команду
  `install.sh agent-upgrade`.
- Предупреждение «tmnode сравнивает резерв с окружением» показывается
  только для отчётов старого `tmnode` (без `reserve_source`).
- Новые ноды ставятся с тегом последнего релиза (`:vX.Y.Z`) вместо
  `:stable`, если в `TM_ADMIN_NODE_IMAGE` тег без версии и релизы включены.
- Образ Docker: `ca-certificates` для запросов к GitHub.
- **Резерв диска под файлы.** Кнопка «Подобрать резерв» и автоподбор при
  установке: 10 % диска (от 512 МиБ до 5 ГиБ), но не больше половины
  свободного места. Нода применяет его без перезапуска.
- `enroll` отдаёт `node_id` строчными: `tmnode` не принимал ULID в верхнем
  регистре.
- Панель: доступность (подписи иконок, язык, TOTP, фокус вкладок),
  компоненты по дизайн-системе, вёрстка на узких экранах, шрифты без
  `data:`-URI (их резал CSP), диалоги и липкие слои без размытия.

Нода и `tmnode` — trustme_backend v0.7.0.

## 0.2.0

Управление нодами — этапы 2 и 6 из docs/PROMPT.md.

- **Новая нода из панели.** Либо одна команда для чистого сервера
  (`install.sh` + `tmnode enroll`), либо установка по SSH прямо из
  панели: пароль или ключ, сверка отпечатка хоста, пароль sudo через
  stdin. Учётные данные не сохраняются.
- **Агент `tmnode`** на хосте ноды присылает heartbeat с отчётом
  `doctor` и статусом настроек, а в ответ забирает желаемый
  `runtime.toml`. Нода применяет его без перезапуска.
- **Лимиты.** Каталог из самой ноды (37 настроек), профиль по умолчанию
  и свои профили, переопределения на ноде. На карточке видно: «применено»,
  «ожидает», «отвергнуто нодой» и что ждёт перезапуска.
- **Звонки (TURN).** Внешние STUN/TURN-серверы и coturn, поставленный
  вместе с нодой; назначение нодам, срок учёток. Секреты зашифрованы и
  наружу не отдаются.
- Ключ, сменившийся на хосте у известной ноды, появляется событием в
  ленте; пин в панели молча не меняется.

## 0.1.0

Фундамент — этап 1 из docs/PROMPT.md.

- **Сервер `trustme-admin`** на axum и SQLite — один бинарь, панель встроена.
  Слушает `127.0.0.1:8088` по умолчанию.
- **Первичная настройка.** Первый владелец создаётся по одноразовой ссылке
  из лога первого старта.
- **Вход.** Пароль (argon2id) и TOTP с запретом повтора кода, сессии в
  cookie (`HttpOnly`, `SameSite=Strict`), CSRF-заголовок, пауза после пяти
  неудачных попыток.
- **Пользователи.** Роли `owner` / `admin` / `viewer`, приглашения
  одноразовой ссылкой, блокировка; последнего владельца не потерять.
- **Ноды.** Адрес, пин, метки, заметки, интервал проб, пауза.
- **Пробы.** Сервер проверяет каждую ноду путём клиента
  (`trust_message_tcp::net::probe`) по расписанию и по кнопке; доступность
  и задержка рукопожатия видны в истории.
- **Отчёты `tmnode doctor --json`.** Приём по токену ноды (`tmnode.report/1`);
  история последних 500 на ноду.
- **Статус ноды** — худшее из последней пробы и последнего отчёта. Смена
  статуса и новые проблемы в отчётах попадают в ленту событий.
- **Сводка парка:** статусы, доступность по часам, медиана рукопожатия.
- **Журнал действий** администраторов.
