# Изменения

## Не выпущено

Управление нодами — этапы 2 и 6 из docs/PROMPT.md.

- **Новая нода из панели.** Либо одна команда для чистого сервера
  (`install.sh` + `tmnode enroll`), либо установка по SSH прямо из
  панели: пароль или ключ, сверка отпечатка хоста, пароль sudo через
  stdin. Учётные данные не сохраняются.
- **Агент `tmnode`** на хосте ноды присылает heartbeat с отчётом
  `doctor` и статусом настроек, а в ответ забирает желаемый
  `runtime.toml`. Нода применяет его без перезапуска.
- **Лимиты.** Каталог из самой ноды (37 настроек), профиль по умолчанию
  и свои профили, переопределения на ноде. На карточке видно: «применено»,
  «ожидает», «отвергнуто нодой» и что ждёт перезапуска.
- **Звонки (TURN).** Внешние STUN/TURN-серверы и coturn, поставленный
  вместе с нодой; назначение нодам, срок учёток. Секреты зашифрованы и
  наружу не отдаются.
- Ключ, сменившийся на хосте у известной ноды, появляется событием в
  ленте; пин в панели молча не меняется.

## 0.1.0

Фундамент — этап 1 из docs/PROMPT.md.

- **Сервер `trustme-admin`** на axum и SQLite — один бинарь, панель встроена.
  Слушает `127.0.0.1:8088` по умолчанию.
- **Первичная настройка.** Первый владелец создаётся по одноразовой ссылке
  из лога первого старта.
- **Вход.** Пароль (argon2id) и TOTP с запретом повтора кода, сессии в
  cookie (`HttpOnly`, `SameSite=Strict`), CSRF-заголовок, пауза после пяти
  неудачных попыток.
- **Пользователи.** Роли `owner` / `admin` / `viewer`, приглашения
  одноразовой ссылкой, блокировка; последнего владельца не потерять.
- **Ноды.** Адрес, пин, метки, заметки, интервал проб, пауза.
- **Пробы.** Сервер проверяет каждую ноду путём клиента
  (`trust_message_tcp::net::probe`) по расписанию и по кнопке; доступность
  и задержка рукопожатия видны в истории.
- **Отчёты `tmnode doctor --json`.** Приём по токену ноды (`tmnode.report/1`);
  история последних 500 на ноду.
- **Статус ноды** — худшее из последней пробы и последнего отчёта. Смена
  статуса и новые проблемы в отчётах попадают в ленту событий.
- **Сводка парка:** статусы, доступность по часам, медиана рукопожатия.
- **Журнал действий** администраторов.
